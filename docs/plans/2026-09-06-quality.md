# Process Lifecycle and Quality Checks

## Execution capsule
**Goal:** Bound child-process cleanup, strengthen type checks and automate validation.
**Context:** The CLI currently owns transport, queue and process handling in one file.
**Constraints:** Keep commands, message envelopes, runtime pins and delivery outcomes stable; add no runtime packages; write explanatory code comments in Korean.
**Evidence:** A 50 ms queue timeout stayed pending after 250 ms with a non-closing fake child; optional strict checks reported 15 diagnostics.
**Success:** Timeout regressions, existing CLI fixtures and stricter checks pass through one command and CI.
**Output:** Focused JS modules, shared child cleanup, tests, CI and updated installation files.

## Design

Keep `sessionctl.mjs` as the CLI and session-metadata owner. Extract App Server transport and native queue execution because they have distinct lifecycles and can be tested without executing the CLI. Share process cleanup and protocol validation only where both callers use them.

At the queue deadline, return `outcome_unknown` using only observed exit metadata. Send SIGTERM to the owned child, then allow 250 ms before SIGKILL and pipe/handle cleanup. The transport uses the same cleanup owner. Cleanup must not imply confirmed delivery or terminate the shared daemon. Tests model non-closing children without spawning resistant processes; any live resistant probe must run in a bounded transient cgroup with `KillMode=control-group`.

The installer and bundle check share one file manifest. Install imported modules before the CLI entry point so the existing three-file installation can be upgraded. Keep the installed skill name and CLI path unchanged.

## Acceptance

### AC01 Timeouts preserve uncertainty and release owned resources

The queue promise settles at its deadline even if close never arrives. Cleanup escalation is bounded, successful/rejected results remain distinct, and proxy cleanup uses the same lifecycle owner.

### AC02 Type and install coverage includes every new module

No optional strict diagnostics remain. A fresh installation and an upgrade from the previous bundle both execute the unchanged CLI entry point successfully.

### AC03 Local and remote checks use the same command

`npm run check` includes all required local checks and is the CI job's entry point. No model request, live message, new runtime dependency or daemon operation is performed.
